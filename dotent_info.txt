# Release Plan

This is a phased rollout strategy designed to minimize risk.

### Phase 1: Initial Release & Beta Testing

- **Preservation of Original `dotnet.yml`:** The original `dotnet.yml` file remains unchanged, ensuring that existing applications continue to function without modification.
- **Opt-In for New Implementation:** Applications can opt into the new implementation by setting `dotnet_build_platform` to `legacy`, `windows`, or `linux`. This allows controlled testing and validation of the changes.

### Phase 2: Final Release

- **Default Value Update:** The default value of `dotnet_build_platform` is changed to `legacy`.
- **Fallback Option (`v1`):** A new option, `v1`, is added to `dotnet_build_platform`. If an application encounters issues with the new implementation, it can revert to the original behavior by setting `dotnet_build_platform="v1"`.

### Phase 3: Cleanup Release

- **Removal of v1 Files:** Once all applications have successfully migrated to the new implementation, the original `dotnet.yml` file will be deleted.
- **Removal of `v1` Option:** The `v1` option from `dotnet_build_platform` will also be removed.
