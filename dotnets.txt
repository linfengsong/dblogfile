
## Best Practices

### IDE Selection Guidance

| Use Case | Recommended IDE | Notes |
|----------|----------------|-------|
| **Python/JavaScript/TypeScript** | VS Code | Lightweight, excellent language support |
| **Java/Kotlin/Scala** | IntelliJ | Superior Java tooling, refactoring |
| **AI/ML with Jupyter** | VS Code | Integrated notebook support |
| **Polyglot projects** | Either | Both support multiple languages |
| **Resource-constrained** | VS Code | Lower memory footprint |

### Performance Optimization

1. **Use warm starts**: Restart workspace instead of creating new when possible
2. **Right-size resources**: Select appropriate VM size for your workload
3. **Monitor resource usage**: Use workspace metrics to identify bottlenecks
4. **Clean up unused workspaces**: Delete inactive workspaces to free resources

<details>
<summary><strong>Resource Monitoring Tips</strong></summary>

- **Check `/proc/meminfo`** for memory usage
- **Use `nvidia-smi`** for GPU utilization
- **Monitor `/home/coder`** storage with `df -h`
- **RDX portal** shows real-time CPU/memory metrics
</details>

## Troubleshooting Common Issues

### Connection Problems

| Symptom | Likely Cause | Solution |
|---------|--------------|----------|
| **"Cannot connect to workspace"** | Network/firewall | Verify network allows connections to RDX domain |
| **JetBrains Gateway fails** | Local IntelliJ missing | Install IntelliJ locally with Gateway plugin |
| **VSCode browser connection fails** | Browser restrictions | Try different browser or use desktop client |

### Performance Issues

| Symptom | Likely Cause | Solution |
|---------|--------------|----------|
| **Slow IDE startup** | Cold start | First startup takes ~61s; subsequent are near-instant |
| **High memory usage** | Insufficient resources | Upgrade workspace VM size |
| **GPU not detected** | Resource allocation | Ensure GPU-enabled template selected |

### IDE-Specific Issues

<details>
<summary><strong>IntelliJ Issues</strong></summary>

- **"Remote IDE not found"**: Wait for IntelliJ extraction to complete (58s on cold start)
- **Plugin compatibility**: Some plugins may not support remote development
- **Indexing slow**: Initial project indexing may take time with large codebases
</details>

<details>
<summary><strong>VS Code Issues</strong></summary>

- **Extension host terminated**: Workspace may be out of memory; increase resources
- **Terminal not responding**: Check workspace health in RDX portal
- **File sync delays**: Network latency between client and workspace
</details>

## Frequently Asked Questions

<details>
summary><strong>Q: Can I use both VSCode and IntelliJ in the same workspace?</strong></summary>

**A:** Yes, you can select both IDEs during workspace creation. The workspace will provision both binaries, though this increases storage requirements.
</details>

<details>
<summary><strong>Q: How do I update my IDE to the latest version?</strong></strong></summary>

**A:** IDE updates are automatic. New workspaces receive the latest version. Existing workspaces continue with their current version until you create a new workspace or the operations team triggers an update cycle.
</details>

<details>
summary><strong>Q: What happens to my settings and extensions?</strong></summary>

**A:** Both VSCode and IntelliJ settings/extensions are stored in your home directory (`/home/coder`) and persist across workspace restarts. They are tied to your user account, not the IDE version.
</details>

<details>
<summary><strong>Q: Can I install custom IDE versions?</strong></summary>

**A:** No, RDX provides standardized, supported IDE versions. Custom versions would break the evergreen update model and N-1 caching. If you need a specific version, contact the RDX team.
</details>

<details>
<summary><strong>Q: How is this different from the old S3-based approach?</strong></summary>

**A:** The new init-container approach:
- Works identically across all environments (AWS, on-premise, etc.)
- No S3 dependency or organizational policy restrictions
- Faster startup (no download latency)
- Better version management with N-1 caching
- Lower operational overhead
</details>

<details>
<summary><strong>Q: What if I need an IDE not currently supported?</strong></summary>

**A:** Contact the RDX team with your use case. The architecture supports adding new IDEs via the same init-container pattern.
</details>
