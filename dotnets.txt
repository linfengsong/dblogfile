### First-Time Startup Performance

| Scenario | Expected Time | What Happens |
|----------|---------------|--------------|
| **Cold Start** (new workspace) | ~61 seconds | IDE binaries are extracted from the init-container |
| **VSCode extraction** | ~3.5 seconds | Minimal overhead for VSCode provisioning |
| **IntelliJ extraction** | ~58 seconds | Larger binary size requires more time |
| **Warm Start** (restart) | ~0 seconds | N-1 version caching bypasses extraction |

<details>
<summary><strong>How N-1 Caching Works</strong></summary>

RDX uses a `VERSION` file tracking system to detect when IDE versions haven't changed:

1. On first workspace creation, IDE binaries are extracted and a version fingerprint is stored
2. On subsequent restarts, RDX compares the current version with the cached version
3. If identical, extraction is skipped entirely
4. This enables **near-instant workspace restarts** after initial provisioning
</details>

## Using Visual Studio Code

### Connecting to VSCode

1. **From the RDX portal**, click "Connect" on your workspace
2. **Select "VS Code"** as your connection method
3. **Open in browser** or use the provided connection URL

### Key Features

- **Full Extension Support**: Install any VS Code extension from the marketplace
- **Integrated Terminal**: Access to container shell with your development tools
- **Remote Development**: All code execution happens in the remote workspace
- **GPU Access**: Direct access to NVIDIA GPUs for AI/ML workloads

<details>
<summary><strong>Troubleshooting VSCode Connection Issues</strong></summary>

| Issue | Solution |
|-------|----------|
| **Connection timeout** | Ensure your network allows WebSocket connections to the RDX domain |
| **Extension installation fails** | Check workspace has internet access via proxy configuration |
| **"Version mismatch" errors** | Rare with new init-container approach; contact support if persistent |
| **Slow file operations** | Workspace may be under resource pressure; consider upgrading VM size |
</details>
