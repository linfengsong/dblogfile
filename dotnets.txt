Leverage APPLICATION (Pipeline) to dynamically select the appropriate runner tag and build image based on information within application project files (`*.csproj`). This will eliminate the need for manual configuration of these settings.

- **Configuration Flag Retirement:** Remove all code related to `dotnet_runner_tag`, `dotnet_build_runner`, and `dotnet_win_version`. These flags will remain for backward compatibility, solely to determine Windows/Linux builds.
- **Windows Support:** Windows builds require a specific .NET SDK version installed on the runner. Several options were considered:
  - **Option 1 (Problematic):** Manually set up the .NET SDK on Windows-2019/2022 runners. This approach cannot automatically incorporate new patch updates from GFED Nexus repositories.
  - **Option 2 (Risky):** Dynamically determine the runner tag at runtime based on the `*.csproj` file's specified SDK version. To use this option, it needs to launch .NET build processing by triggering a child pipeline. GitLab has limitations regarding artifact support between parent and child pipelines. The detailed risk issues have been documented in the Risk Assessment.
  - **Option 3 (Not Recommended):** To reduce implementation risk and avoid triggering a child pipeline, the Runner Tag and GITLAB job stage rule condition cannot be dynamically set from the application '*.csproj' TargetFramework. Instead, add two additional inputs: `dotnet_win_runner` and `dotnet_nuget_publish` to cover this restriction.
  - **Option 4 (Recommended):** Always use `windows-2019/vs-legacy` with net6.0 and net8.0 frameworks. This CTO requirements for retiring .NET 6.0, as APPLICATION would always select this version but has been agreement with CTO to use this solution and APPLICATION would maintain application usage on Legacy version. The recommended solution is Option 4. **We prefer** to reduce the complexity of .NET runner setup for applications.

APPLICATION pipeline defines a fixed runner version in the variable `windows-2019/vs-legacy` and applies it to all Windows Build job’s `runner_tag`.
