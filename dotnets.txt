### Step-by-Step Workspace Creation

1. **Access RDX Portal**: Navigate to the RDX web interface
2. **Select Template**: Choose from available templates based on your task
3. **Configure Parameters**:
   - Enter workspace name
   - Select tenant from dropdown
   - Adjust CPU, memory, and storage as needed
   - Provide GitLab token
   - Add optional repository URLs
4. **Review Entitlements**: Verify automatically injected capabilities
5. **Create Workspace**: Click "Create" and wait for provisioning (typically 2-5 minutes)

<details>
summary><strong>Workspace Creation Tips</strong></summary>

- **Name Convention**: Use descriptive names like `project-feature-branch`
- **Resource Sizing**: Start with recommended defaults, adjust based on usage
- **GitLab Token**: Use a token with "api" and "read_repository" scope
- **Dotfiles**: Use your personal dotfiles repo for custom shell configurations
- **Tenant Selection**: Choose the tenant matching your team/project requirements
</details>

### Workspace Management

| Action | How To | Notes |
|--------|--------|-------|
| **Start/Stop** | Portal toggle or auto-stop after inactivity | Saves resources when not in use |
| **Resize** | Edit workspace parameters | Some changes require restart |
| **Clone** | Create copy from existing workspace | Useful for testing configurations |
| **Delete** | Remove from portal | Irreversible - backup code first |
| **Share** | Generate shareable link | Granular permission controls |

## Best Practices

### Template Selection Guidelines

1. **Start General**: Begin with RDX-General unless you have specific analytics needs
2. **Specialize Gradually**: Move to specialized templates as requirements become clear
3. **Consider Team Needs**: Choose templates that match your team's common workflows
4. **Evaluate Resource Usage**: Monitor workspace metrics and adjust template/resource selection
