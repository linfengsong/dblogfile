- **Linux Support:** Due to Docker image limitations (supporting only one SDK version - net6.0 or net8.0), Linux builds will select the appropriate image based on the target SDK version. Multiple Target Frameworks are supported on Linux in this design but it only can test one Target Framework since restriction of .NET SDK.
- **Windows Support:** Windows builds require a specific .NET SDK version installed on the runner. Several options were considered:
  - **Option 3 (Recommended with Risk):** Dynamically determine the runner tag at runtime based on the `.csproj` file's specified SDK version. To use this option, it need launch .NET build processing by trigger child pipeline. GITLAB has limitation of artifact support between parent and child pipeline. The Detail risk issue has been documented at Risk Assessment
  - **Option 4 (Recommended): To reduce implementation risk and avoid to trigger child pipeline, the Runner Tag and step rule condition cannot dynamic setup from application `csproj` `TargetFramework`,  add two additional inputs: `dotnet_win_runner` and `dotnet_nuget_publish` to cover this restriction. 

The recommended solution is Option 3 or 4, as it allows for automatic selection and keeps things updated without manual intervention with minium inputs. Option 4 solution is to choice to reduce risk of option 3 solution.
