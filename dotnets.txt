The current implementation relies on numerous inputs from .NET GitLab components to determine how .NET builds are executed. These inputs require proper setup of application GitLab configurations during the initial installation to ensure the pipeline functions correctly. Any changes made to this system face a high risk of introducing issues since the existing test coverage for the .NET pipeline is very low. Enhancing the tests involves manually modifying test cases or end-to-end (e2e) test cases within the .NET sandbox environment. However, after testing is complete, most of these test cases are lost, making it difficult to reuse them for testing new changes.
